# CI reliability and dependency audit investigation

[Issue 308](https://github.com/link-foundation/js-ai-driven-development-pipeline-template/issues/308)
requires the seven fixes and their closing references in one pull request.
The downstream incidents in [voice-simulator PR 116](https://github.com/konard/voice-simulator/pull/116)
and [sensitive-data-sanitizer PR 209](https://github.com/link-foundation/sensitive-data-sanitizer/pull/209)
provide working examples of the lint, timeout, and deprecation checks.

| Issue | Requirement and cause                                                                                                                                                                                                               | Options and implementation                                                                                                                                                                                                                                                                                         | Verification                                                                                                                                                                                                                                         |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| #301  | Keep all errors, warn across changed files, and warn across the repository when lint configuration or pins change. A body-only edit can move a function over the complexity threshold while ESLint reports at its unchanged header. | Whole-repository lint on every PR would surface unrelated warnings. AST mapping would require rule-specific treatment. Use NUL-delimited Git paths and the staged-file hook's warning scope. Include committed, staged, unstaged, and untracked changes. Trace the selected base and paths with `LINT_VERBOSE=1`.  | In a scratch Git repository, a body-only edit makes the normal lint entry point report line 1 and exit 1. Unit tests cover untouched files, errors, and config changes.                                                                              |
| #302  | Remove the vulnerable parser from the artifact transport lock. GitHub lists 5.12.0 as the first fixed release.                                                                                                                      | A manifest override would add another pin to maintain. The existing Azure SDK range accepts the patched version, so use npm audit fix in lock-only mode. Dependabot would automate future updates and is optional in the issue.                                                                                    | The lock resolves 5.12.1. The unchanged Security policy reports zero advisories. The artifact transport regression passes.                                                                                                                           |
| #303  | Remove the deprecated Secretlint preset install and preserve secret detection. The official preset is built into Secretlint 14.                                                                                                     | A locked dev dependency would also work but would move the scan after the project dependency install. Pin the standalone CLI to 14.0.0 and preserve the existing rule ID.                                                                                                                                          | Pin and config assertions plus clean, plain-text, and gzip scanner probes.                                                                                                                                                                           |
| #304  | Put wrapper warnings, timeout and survivor errors, and progress lines on separate log lines. A child can emit binary or text output without a newline.                                                                              | An unconditional newline is viable when capture is disabled. For captured output, inspect the last byte of each relayed range and close only open streams before wrapper output.                                                                                                                                   | Regression cases cover NUL-terminated stdout, partial stderr, completion, and timeout. The existing process-group and exit status tests still apply.                                                                                                 |
| #305  | Bound the 15 reported installs and check all workflows, local composite calls, and quoted wrapper paths against 70% of the job backstop. The old check covered one workflow and matched the raw YAML as text.                       | Use the existing YAML parser for the workflow and action structure. Check shell command boundaries for recognized install and download entry points. Count each composite invocation and sum budgets that can run together. Use workflow linting for syntax and keep this repository's budget policy in its tests. | The scan covers every checked-in workflow and action manifest. Fixtures cover nesting, repeated calls, quoted paths, offline commands, and overlapping conditions. The scan also found unbounded ShellCheck, zizmor, Deno, and tool bootstrap calls. |
| #306  | Look up current registry metadata for each locked package version. Warn on PRs, fail on the weekly schedule, and fail on any lookup error. npm only refreshes lockfile metadata when it resolves a package.                         | npm's pacote can retrieve manifests, but the exact-version endpoint and built-in fetch avoid installing dependencies in Security. Deduplicate per lock and limit requests to eight concurrent lookups with individual deadlines.                                                                                   | Mock tests cover a stale lock, scoped aliases, and error paths, and exercise the CLI exit policy. The live check verified 846 versions across three locks.                                                                                           |
| #307  | Restore passing Security audits for the root and app locks while keeping development dependencies and existing thresholds.                                                                                                          | A reviewed release or backport was appropriate while the advisory was active. GitHub withdrew it on November 18, 2026. The strict live audit now passes on both original locks, so the dependency graph needs no change for this issue.                                                                            | The existing audit reporter returned zero advisories for both locks with `AUDIT_LEVEL=high AUDIT_FIXABLE_LEVEL=moderate`.                                                                                                                            |
